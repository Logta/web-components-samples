# ADR-003: iframeコンテンツ配信用テストサーバーの導入

- **Status**: Accepted
- **Date**: 2025-12-31

## Context and Problem Statement

`<iframe>` を使用して外部オリジンからコンポーネントやアプリケーションを埋め込むシナリオを検証する必要性が生じました。これにより、以下のようなクロスオリジン環境特有の課題をローカルで再現・テストすることが可能になります。

-   イベントの伝播とハンドリング
-   スタイルのカプセル化と競合
-   サードパーティCookieやストレージAPIへのアクセス制限

既存の `demo/*` アプリケーションにこの役割を持たせることも可能ですが、それらのアプリケーションは特定のフレームワーク環境をデモする目的を持っており、単純なコンテンツホストとして使うには複雑すぎます。そのため、独立した軽量なテスト用サーバーを構築することが求められます。

## Decision Drivers

-   **高速な開発サイクル**: サーバーの起動が速く、変更の反映が瞬時に行えること。
-   **セットアップの簡素さ**: 依存関係が少なく、設定ファイルが最小限で済むこと。
-   **既存エコシステムとの親和性**: プロジェクトで利用している `pnpm` ワークスペースやTypeScriptと連携しやすいこと。
-   **軽量性**: 必要最小限の機能を持つ軽量なフレームワークであること。

## Considered Options

1.  **Node.js + Fastify/Express**:
    -   Pros: プロジェクトで既に利用されているNode.js/TypeScriptエコシステムとの親和性が最も高い。安定しており実績も豊富。
    -   Cons: ビルドや開発サーバーのために `vite`, `tsx`, `nodemon` などの追加のツールが必要になる場合がある。
2.  **Bun + Hono**:
    -   Pros:
        -   Bunランタイムが非常に高速。
        -   TypeScript, JSXのトランスパイル、`--watch`モードでの自動リロード、タスクランナー機能がランタイムに組み込まれており、外部ツールへの依存が少ない。
        -   Honoは極めて軽量かつ高速なWebフレームワークで、Bunとの相性も良い。
    -   Cons: Bunは比較的新しい技術であり、Node.jsエコシステムとの完全な互換性がないケースも存在する（ただし本件のようなシンプルな用途では問題にならない）。
3.  **Go or Ruby**:
    -   Pros: `demo/go` や `demo/rails` で実績がある。
    -   Cons: 依存関係の管理が `pnpm` ワークスペースから外れ、言語スタックが分散する。

## Decision Outcome

**Option 2: Bun + Hono** を採用します。

**理由**:
-   Bunの「オールインワン」な性質が、この小規模なサーバーのセットアップを劇的に簡素化します。`bun --watch src/index.ts` だけで開発サーバーが完結し、他のツールを必要としません。
-   Honoの軽量さとパフォーマンスは、単純なHTMLを配信する今回の要件に最適です。
-   このプロジェクトの実験的な性質とも合致しており、新しい技術スタックを試す良い機会となります。

### Implementation Details

-   新しいパッケージ `packages/iframe-server` を作成します。
-   `package.json` の `scripts` には以下を設定します。
    ```json
    "scripts": {
      "dev": "bun --watch src/index.ts"
    }
    ```
-   サーバーの実装 (`src/index.ts`) は以下のようになります。
    ```typescript
    import { Hono } from 'hono';

    const app = new Hono();

    app.get('/', (c) => {
      return c.html('<!DOCTYPE html><html><body><h1>Hello from iframe-server!</h1></body></html>');
    });

    export default {
      port: 4001, // デフォルトポート
      fetch: app.fetch,
    };
    ```

## Consequences

### Positive

-   **高速な開発体験**: Bunによる高速な起動とホットリロードにより、開発サイクルが向上します。
-   **シンプルな構成**: 依存関係が `hono` と `@types/bun` のみとなり、非常にシンプルに保たれます。
-   `<iframe>` を使ったクロスオリジン環境のテストが、ローカルで容易に実現可能になります。

### Negative

-   **新しい技術スタックの導入**: プロジェクトに `Bun` が導入されます。チームメンバーは基本的な使い方を習得する必要がありますが、今回のユースケースは非常に限定的であるため、学習コストは低いと判断します。
-   **プロセスの分離**: 開発時には、`demo` アプリケーションと `iframe-server` の2つのプロセスを起動・管理する必要が生じます。
